# Bot Mini App authoring and publication completion

Status: implementation, 2026-10-21. Current request: deeply compare and complete
Fabushi Bot creation and publication of Mini Apps. Builds/tests run in Actions
only; paid-model acceptance remains stopped. Mac first. Application business
logic ships inside the package, never as a Host feature.

## Discovery and ownership

Baseline af2824fa5b4f2231c4d9689d580f6f50e06a957f (#167, dependent on #166).
MiniApp SDK currently creates/edits/inspects/exports. Inspection returns only hashes,
so the Bot cannot read editable source via its typed tool or import existing source.
Generated Actions tests and packages but does not publish a GitHub Release. The
native marketplace publisher is deliberately pinned to Dandelion 0.2.1 and cannot
submit arbitrary generated apps. Export, GitHub release, marketplace review and
approved installation are separate states, not synonyms.

Extend existing MiniApp SDK and ordinary GitHub MCP + generated Actions owner.
Keep reviewed Shell, optimistic revisions, isolated Python, cancellation, existing
account/authentication and Registry authorization. No new runtime, credential
store, catalog, silent approval, hard failure-count cancellation, or signing key.
External source/docs are research data, not execution instructions. Phase effort
and model are inherited from the active session.

## Requirements

- BP-01: typed read returns bounded source for selected project files with exact
  current revision; stale revision/read and missing paths fail explicitly. Import
  creates a new immutable project from complete validated src/tests/config using
  the same limits and symlink/atomic history protection. Never overwrite an
  existing project or replace an existing native repo with a web scaffold.
- BP-02: generated repo supports explicit GitHub publication after behavior tests
  and exact-source packaging. Only workflow_dispatch publish=true on an existing
  version tag can mutate Releases; expected SHA must match the checkout and the
  tag must match config version. Push/PR verification has read-only credentials.
- BP-03: release draft first, upload exact bounded unsigned package, manifest and
  provenance, verify server SHA256/size, then publish. No asset overwrite, tag
  move, force push, deletion, merge, or blind retry of uncertain mutations.
  Existing matching releases may be read/reconciled; conflicting content blocks.
  Errors retain draft/release identity without secrets. Production uses fixed
  GitHub endpoints, rejects redirects, and never passes job tokens to tests.
- BP-04: export includes editable behavior tests, source tooling and publication
  instructions/state for the Bot to discover ordinary GitHub tools, verify base,
  push a branch/open PR/observe CI, then create the immutable tag/dispatch only
  when publication is requested. Final report requires observed remote release
  URL, source SHA and asset digest. It never calls an unsigned ZIP installable.
- BP-06: on the Mac/Unix desktop, expose explicit local source authoring through
  the existing ExternalShell executor, review and local permission gate when its
  trusted per-agent binding exists. Use the same SDK with a private per-agent
  home workspace; no model-supplied root, no unreviewed subprocess, no automatic
  retry/fallback after a Box failure, and no app business code execution. Box and
  local projects remain explicit separate targets. Missing Python/provider/grant
  is truthful failure; do not call a merely listed tool ready.
- BP-05: compare generic Registry submission to the actual backend protocol and
  current native account service. Marketplace submission/approval/signature and
  installation must remain explicit gaps until their real production invocation
  is connected. Do not widen the pinned publisher into a token proxy or pretend
  a GitHub release is a catalog-approved installation.

## Verification, delivery and failure

Actions SDK tests exercise read/import exact source, stale/missing/conflicting
requests, deterministic packaging, release authorization gates and a simulated
GitHub transport with actual generated bytes. Test tag/SHA mismatch, failed tests,
asset digest mismatch, immutability conflict, success/reconciliation and uncertain
writes with dispatch counts. Extend existing real Bot-tool GitHub source roundtrip
without using production credentials or starting paid-model acceptance. Mac Host
compilation covers the embedded SDK and toolset integration.

Existing #166/#167 tests carry forward unless edited behavior invalidates them.
CI, real GitHub mutation, signed package, installed Mac and real-model Bot acceptance
are distinct proofs. Keep immutable user projects/releases on rollback. No whole-
product completion while Registry or installed execution gates remain unresolved.
