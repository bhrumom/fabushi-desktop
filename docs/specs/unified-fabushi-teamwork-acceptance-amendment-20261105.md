批准在既有授权内推进 M1 文件实施；以下纠偏必须成为 ORIGINAL_REQUEST/PROJECT_PLAN 的一部分：

1. 该 prompt 的 acceptance 列表是首批局部验收，绝不替代 UFX-AC01..09 与完整 FBCP/TDRP/OCRM gates。R4 不能停留在映射/治理；M3、M4 必须实际实现、接线和验证全部锁定产品职责。M1 或静态审查完成后继续后续无依赖实施；不能触发全项目胜利声明。
2. 200–600 行是新内聚领域模块目标，不要求把现存 ProductionRenderer 等几千行根文件在此次修复一次性重写为 600 行。根文件只允许窄接线；不得为符合字数删除功能、极端压缩代码或做无关重构。
3. 恢复一个 canonical Composer，优先重新使用已有完整组件并以 typed actions 扩展，不能再造外观相同的第二输入器来补合同。模型/权限没有真实 owner 时临时隐藏只表示未配置/待实现，不是完整能力已交付。
4. 文件阅读/静态审查能证明部分引用/合同事实，不能证明交互、语法编译、网络、性能或安全运行正确。禁止把“通过静态语法分析”写成已执行 parser/compiler；没有实际运行就 not-run。
5. 团队自己的 run_command 拒绝保持不绕过、不换工具执行同一个被拒动作。文件实施可继续。外部集成/CI 步骤需列出具体变更与命令/接口及权限要求，由委托方在其既有授权与工具边界内单独判断，不假定所有能力永久不可用。
6. 现有源码状态 c0702aa11（含三份设计文档提交），不是服务运行/安装证据。不要把旧 release/main 当新候选。代码编辑后状态由事实更新，不能复用旧 head 的验证结论。

最终验收权在 Codex；实际发布仍要求原项目独立 ACCEPT。该审阅不批准未看到的代码、不授权命令绕过、不批准产品发布。
