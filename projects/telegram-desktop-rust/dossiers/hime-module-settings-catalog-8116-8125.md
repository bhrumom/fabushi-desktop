## Responsibility synthesis

The module callback/main-function quartet contributes capability negotiation and lifecycle, not a source runtime. Required initialization fails closed; optional reset/preedit/key/visibility/flush/setup functions are explicit capabilities; candidate/preedit/commit/mode/shape state must remain in source-neutral canonical owners and be fenced across focus, composition generation, cancellation and owner replacement.

The phonetic conversion pair contributes deterministic Resource behavior: validated UTF-8 parsing, bounded phrase storage, duplicate removal, stable ranking/order, portable serialization, atomic publication, explicit reload/invalidation, and deterministic diagnostic/export reads. The Hime CLI and X11 reload message are replacement-only.

The settings trio contributes a typed/defaulted input-settings schema and invariants rather than a second Settings product. Default/enabled/cycle relationships, candidate matching/autoselect/autocommit policies, width/script/input toggles, feedback/accessibility preferences and coupled preedit-display controls belong to existing canonical Settings/platform-input/Composer/Resource/design-system owners. The source unauthenticated remote-client port is not retained; any applicable remote input capability must use Fabushi authentication, authorization, persistence, retry/recovery and service contracts.

## Current production boundary

The descendant renderer already reports truthful Chromium IME focus/composition start-update-end lifecycle, monotonic composition generation and preedit presence through the canonical editor status contract. That is not native OS input-source truth. Input method identity, language, width mode, script variant and candidate state remain explicitly unknown until a source-neutral native platform adapter reports them. Browser locale or source-shaped Hime/XIM/GTK runtime is not an acceptable substitute.
