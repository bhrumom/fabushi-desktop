## Consumer decomposition

- 369-380: `calls.style` and `ui/chat/chat_style.style` use answer, incoming/outgoing arrow and camera-active assets for active-call controls and call-history transcript entries.
- 381-389: `calls.style` uses camera-muted, cancel and discard assets for media/decline/end affordances; `calls_panel.cpp` binds accessible cancel/decline semantics.
- 390-404: ended/group/message/rating assets span post-call, transcript and group-call presentation. `calls/group/calls_group_panel.cpp` has the group-call message action.
- 405-430: recording, add-people, overflow, mute indicators, present/screen-share, settings and shadow resources are group/active-call controls and decoration.

## Canonical Fabushi owner and production gap

Current Fabushi already has a single shipping Human call surface in `frontend/src/production/human-call-media.tsx`, a Host `CallSession` state owner, and gateway routes for create/sync/transition/media/signaling. It provides incoming accept voice/video, decline, mute, camera, screen sharing and hangup.

That does **not** close the entire Telegram-derived responsibility. Current Host code enforces shipping Human calls as exactly the authenticated Human plus one peer. Therefore Telegram group-call responsibilities evidenced here—group call identity/history, in-call message, add people/participant mutation, call recording and broader group-call settings—remain production-open. They must extend the canonical Human-call domain; no parallel TelegramGroupCall state/UI owner is allowed.
