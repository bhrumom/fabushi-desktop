## Physical publication contract

LFP-01: Rust owns a typed publication disposition: `not_published`, `published`, or `outcome_unknown`, plus a bounded physical phase and `publicationObserved`. Known nonpublication requires the producer to remain before the namespace publication primitive. Set the possible-publication phase before invoking that primitive. Any unclassified failure after entry is unknown; do not infer nonpublication from error text, broad errno classes, successful cancellation, cleanup, process exit or response loss. If rename/link success was observed before later failure, retain `publicationObserved=true` even while overall disposition is unknown.

LFP-02: A successful publication receipt contains the validated SHA-256, size and version, and identifies the operation, request and transfer where applicable. Every parsed native request requires the exact existing bridge requestId before publication can be entered. Every native response echoes a versioned contract, the exact existing bridge requestId, native op, and optional transferId. These fields establish correlation under the existing authenticated provider boundary, not a cryptographic execution attestation. write-atomic also requires request binding; it must not escape classification merely because it lacks a transfer ID.

LFP-03: Native validation, root/path anchoring, size/hash/version checks, disk-space bounds, stage ownership and existing no-follow/reparse checks remain in Rust. POSIX successful receipt includes the existing stage/file and parent barriers; a failed barrier after publication is unknown. Windows successful receipt confirms the current handle rename contract; no power-loss or unsupported filesystem guarantee is inferred. Returned digest/version records the validated producer bytes, not perpetual immutability after another writer edits the target.

LFP-04: The existing validation-to-publication stage/target identity window is a separately recorded security boundary, not proved closed by receipt correlation. A stronger atomic expectedVersion/CAS or hostile-concurrent-writer guarantee may not be claimed without the corresponding same-object publication implementation and adversarial oracle. Preserve current checks; retain this explicit acceptance gap if outside the selected repair. Do not silently broaden the sandbox contract or call current digest metadata proof of a stronger guarantee.

## Thin transport and response correlation

LFP-05: The TS native helper reports owned child facts and forwards Rust disposition. It waits for stdio closure before decoding, keeps bounded stdout/stderr, and handles spawn, stdin, process, close and output-cap failures without unhandled errors. A definite refusal before a child can receive the request can report non-entry. Once entry is possible, absent or invalid bound disposition is unknown for publication-capable requests. Killing a child or closing a transport cannot prove nonpublication. Request cancellation must address the exact owned child; process lifetime must never be inferred from a recycled numeric PID.

LFP-06: Provider upload state is an adapter ticket, not a durable truth store. Reserve the exact request ticket before asynchronous approval/path work and the transfer ticket before asynchronous start work; recheck its cancellation before helper entry. Only the admitted current request may change, retire or clean up its own ticket. A duplicate request ID must not manufacture a terminal response for the already admitted request. Duplicate, wrong-path, stale-phase and concurrent refusals must not abort an older valid transfer. Keep commit ownership until settlement, including ambiguous helper failure. Forward native phase/disposition unchanged; generic exceptions after possible helper entry cannot become known nonpublication. A truncated oversized-frame prefix that supplies only requestId cannot manufacture a fully bound refusal receipt. Existing download, atomic upload and other provider routes remain supported.

LFP-07: Rust validates phase-specific acknowledgments. Start must identify start with zero staged bytes; chunk must identify chunk and the expected cumulative size; commit must carry the exact bound publication receipt and expected digest/size/version. Untagged, malformed, wrong-phase or contradictory commit acknowledgments cannot establish known success or refusal. Start/chunk failures may be known with respect to final-target publication only while no commit request could have been dispatched. Preserve existing upload bounds and permission checks. No automatic effect retry is added.

## Shared wire and Rust contract

The publication object is `{ contract: "LFP-v1", requestId: string, op: string, transferId?: string, disposition: "not_published" | "published" | "outcome_unknown", phase: "validation" | "staging" | "publication" | "stage-cleanup" | "directory-sync" | "complete" | "bridge-pre-entry" | "transport", publicationObserved: boolean }`. RequestId is required and nonempty. TransferId is required and equal for upload-start/chunk/commit/abort and absent for other operations. Native op uses the existing helper names, including write-atomic and read; it is not inferred from a reply's kind alone.

The helper process envelope retains `ok`, `value` or bounded `error`, and adds the publication object. Provider file/file-error frames preserve that same object. Start and chunk success have not_published/false with size 0 or the exact cumulative size; commit and atomic-write success have published/true/complete and valid digest/size/version. An unknown outcome may have publicationObserved true or false. Not_published must not have publicationObserved true. Malformed/untagged/contradictory publication-capable responses remain unknown after possible entry.

The existing Rust native module owns the shared publication/disposition types and their validation. Its actual environment wrapper and direct native contracts use the same production classification path. The gateway uses that same Rust contract to validate the correlated receipt. TS types are wire projections and process observations, not independent publication truth. The existing source-neutral Box transfer error preserves an uncertainty classification and contextual text; the production adapter maps that classification to the existing ProviderSessionError variant.

Keep source-only test fault seams separate from production protocol. No environment variable, frame field or shipping public switch may manufacture a successful publication or choose a test failure. Bounded controlled failures around a real publication are explicitly qualified as synthetic fault evidence; physical filesystem/device acceptance stays separate.
