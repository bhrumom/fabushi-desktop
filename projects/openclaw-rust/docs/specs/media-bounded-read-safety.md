## Requirements

| ID | Required behavior and causal oracle |
| --- | --- |
| BR-01 | Support every usize cap without overflow. A tiny nonempty file at usize::MAX returns its exact bytes. The real service checked-converts parsed u64 to usize and explicitly errors if unrepresentable; do not wrap, silently saturate, change to a default or impose a new lower global limit. Existing omitted/non-u64 option handling is preserved. |
| BR-02 | Return exact bytes only after EOF within the cap. Preserve empty-at-zero and exact-cap success. Preflight oversize and actual growth beyond cap return InvalidData, never a successful truncated prefix. Detect one extra byte without overflowing cap arithmetic or growing the returned vector beyond the cap. Handle short reads and Interrupted using ordinary Read semantics. |
| BR-03 | Retain early ordinary-file and size checks, then admit kind and size on the actual opened owned handle before buffering. Continue through that same handle. Preserve NotFound for nonregular files and ordinary OS/open/read errors otherwise. Rechecking is not proof of original pathname identity or immutable contents. |
| BR-04 | Open a fresh Unix descriptor with O_NONBLOCK so a regular-file preflight followed by FIFO replacement cannot wait for a writer. Preserve ordinary symlinks and hardlinks; do not add O_NOFOLLOW or a blanket Windows reparse ban. Windows uses its existing ordinary open path plus actual-handle checks; hostile Windows namespace/open deadlines remain separately open. |
| BR-05 | No whole-metadata reservation. Use at most 64 KiB scratch and at most 64 KiB initial heap reservation; a zero initial reservation is allowed. Grow fallibly from actual bytes with amortized allocation rather than repeatedly copying the full accumulated buffer. Allocation failure becomes an I/O error, never false TooLarge or empty success. Retain no shared cache or allocation state. |
| BR-06 | Preserve all eight existing caller expressions, per-caller limits, root checks and error/Option/skip projection. Actual Attachments loadWebMedia consumes corrected bytes/errors. Keep HHP explicit HTML admission, cap/root controls and absence of generated trust. |
| BR-07 | Each attempt opens a fresh owned handle; every return or failure releases only its handle. No success, upload entry, durable marker or new file is created by a failed read. An ordinary retry after replacement uses fresh bytes. No background worker, replay or cleanup scope is added. |
| BR-08 | maxBytes/path/host_read_capability/has_read_file/htmlPublication do not supply principal, scope or permission authority. Existing root/ancestor identity, real callback transport selection, revocation/cancellation and Windows hostile-open gaps remain required separate work. |
| BR-09 | Freeze the complete owner/consumer/spec/test/capture/accounting change. Require fresh independent source review and exact-H native Actions with real ordinary-file consumers, causal mutation controls and original logs/inputs/exits. Do not promote global, source-reading, wiring, verification or acceptance state from source work alone. |

Result allocation remains proportional to accepted bytes; fallible growth is not a guarantee against all process-wide memory exhaustion.
