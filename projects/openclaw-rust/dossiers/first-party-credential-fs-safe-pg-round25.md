### New high-confidence static contract failure: producer "issuer" vs Host deny_unknown_fields

The **producer always emits an "issuer" property** in JSON v1 at fabushi-account-service.ts L199-207. The Host type FabushiCoreCredentialFile in auth_service.rs L76-85 uses serde(rename_all="camelCase", deny_unknown_fields) but declares **only** version/access_token/expires_at_ms/session_id/device_id/user_id. The reader at L421-425 calls serde_json::from_str and maps any error to unavailable. Therefore, under the frozen source, an unmodified, successfully written first-party v1 payload contains an unknown field and fails Host deserialization. This is deterministic source-to-source incompatibility; **it is not a newly executed failing test or proof of runtime distribution**. Stable finding **OCRM-F25-AUTH-ISSUER-DENY**, severity blocking first-party Core credential use when this reader is exercised. Neither treating the generic Cursor secret map as writer nor removing issuer without reviewing issuer-binding security semantics is an acceptable fix. Trace the actual Core credential consumer and decide the typed schema/version policy through the existing Host Auth owner before a scoped test/fix.

Additional negative oracles requiring Actions and integration evidence:
- A valid Electron-produced first-party v1 credential with issuer must be accepted only for its allowed issuer, account, session, device and expiry; malformed or foreign fields/identities must fail closed according to explicitly reviewed version policy.
- A->B account switch with pending refresh and lost rename/Host read must never authorize A after B settles; Host restart and revoke must not resurrect A.
- A failed fs.writeFile may leave a temporary containing a secret; a swallowed failed unlink/chmod does not establish secure revocation, cleanup or effective file mode. Prove account ownership and OS ACL, atomicity, fsync policy, no diagnostic/artifact token leakage and error reconciliation.
- A generic Gateway bearer, OS machine ID, Cursor inference renewal token or remote-device secret is not an operator.pairing grant. Preserve the independent Rust pairing-authority owner requirement.

It contains no rollback transaction. native/src/task.rs blob 98a263b7ac0713b2da4a59bf8e2e429c6d63c231 L1-91 registers AbortSignal -> AtomicBool; abort is cooperative and does not undo completed OS writes.

Native POSIX functions: native/src/unix.rs blob eb1a2410e7f37fa2348ea1bdb8256e867954a2d2, L1-485 read continuously plus macOS path resolver L1510-1690. mkdir_beneath L220-236 descends retained descriptors, creates each component with mkdirat and permits EEXIST before opening a directory. write_archive_file L432-453 creates an exclusive fresh file via root-constrained open, copies at most expected_size+1 from the source, then compares copied count, flushes and applies fchmod; **if more than expected bytes arrive, it may already have written one extra byte before returning an error**. ### Wrapper staging and cancellation: distinguish private stage from published destination

src/archive.ts blob b61a198fec4823974643bc32db754b31a9df039a L320-389 calls native inspect and extract **inside withStagedArchivePublication**, creates a temporary extraction directory and passes its FD to native; modes passed to native are 0700 directory / 0600 file, with the separately reviewed admitted final plan. Thus a native partial write occurs in a private **staging** root, not automatically in the final destination.

src/archive-staging.ts blob 00aaf9be3c9bac10a83bdc10d88b373a36a28ff4 L327-364 chooses temp root outside destination, uses mkdtemp and directory identity guard, then attempts recursive removal in finally; cleanup failure can be swallowed, and an identity mismatch deliberately preserves staging rather than risking wrong-path deletion. This is best-effort guarded cleanup, not a proof of no surviving stage after errors.

src/archive-merge.ts blob a837b18ed8506cecbe747bcca9277cd728af3fdd, inspected all source content L1-279. withStagedArchivePublication validates plan, calls mergeTree after successful extraction. mergeTree walks the staging tree and issues targetRoot.copyIn per file; each successful published destination mutation can precede a later failure/cancel. The source explicitly notes that merge does not gain rollback authority. Therefore a cancellation **before merge** generally avoids publication (subject to cleanup), whereas cancellation **during merge** may leave an already published subset; returning timeout does not imply full rollback. src/archive-deadline.ts blob 8a2fe6216b97a0f54ea6e1077a317c653e40aa02 L65-130 retains destination mutation ownership and awaits active mutations during timeout unwind, which prevents orphaned operations but does not roll back completed publication. src/archive-durability.ts blob c406830a1ff41a8452c93764cc39dda7f918bd46 L1-132 coordinates optional syncing; durability option defaults false in src/archive-plan.ts blob 8ed43d5b66ed0f23a4f582a200883ecaf5476539 L180-195.

FS negative oracles: corrupted or cancelled TAR/ZIP must not publish if failure occurs during inspect/extract; interrupted merge must report or reconcile already published identities before restart; duplicate destinations, symlinks/reparse points, hardlinks, destination replacement, mode/ACL and temp-directory failure must remain fail-closed and non-destructive to unrelated files.
