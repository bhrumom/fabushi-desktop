## R29-AUTO-STOP-01 — asynchronous completion remains callable after worker suspension/stop

- Exact target \`source/host/src/extensions/automations/production.rs\` blob \`3927e9736bebd27302cd9c4c2139b583e80b7aa4\` L157-202: the poll worker first collects backend fires, then dispatches outside the fire mutex. Its completion callback captures \`event_id\` plus \`Arc<Mutex<AutomationFireBackendRuntime>>\`, and on late completion calls \`state.complete\` (or \`abandon\`). It does **not** capture/compare an authentication principal, account generation, or stopped generation. L227-249 suspends by setting wake suspended plus fire.stop; L263-297 stops worker and joins it, but does not join independently spawned fire execution workers or revoke their retained completion closures.
- Exact \`source/host/src/extensions/automations/sand_automation_fire_consumer.rs\` blob \`b38b1614a95a34bbfe34acff39b8c3cdfaae943e\` L151-163: \`stop()\` sets \`stopped=true\`. L227-242 \`tick_with_state\` correctly blocks **new polls** while stopped/not-ready. But L187-208 \`complete\` has **no** stopped-state check: for a still-known event ID it inserts a completed state and immediately calls \`report_completion\`. L358-372 posts to \`/sand/automation-runs/complete\`. Therefore, a retained callback **can attempt a Sand HTTP completion report after poll suspension or runtime stop**. This is a direct source-call-path conclusion, not evidence the backend accepted such a report, that an account switch occurred, or that external work was cancelled. The older observation of detached callbacks now has a precise post-stop write path and falsifiable boundary.
- \`source/host/src/extensions/automations/production_lifecycle.rs\` blob \`acc5d67aef35ede93a0f87e317f966013ee2eb8b\` L430-482 delegates wake suspension/resumption/stop to \`backend\`; it does not add a generation tag to previously issued completion closures. \`backend_transport.rs\` blob \`6dc4477c72a38179d71ab33013c9b7e2c3b89991\` L65-96 fetches **current Sand/Cursor bearer** for each operation; it is not first-party Fabushi Core auth.
