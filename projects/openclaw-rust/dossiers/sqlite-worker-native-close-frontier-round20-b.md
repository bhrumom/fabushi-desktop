## 2. Source-backed, falsifiable lifecycle contracts (NOT executed tests)

**PAIR-R20B-01 — native worker task host replies do not finalize cleanup.** `worker-task-server.ts` L73-132: closeResource waits preceding execution, performs cleanup and sends `{ok:true}` only after its Promise resolves; sends error detail on failure, then closes the separate receipt port. L134-168 requires active task ID and response ID and acknowledges `consumed` only when reply actually consumed. L172-248 serializes tasks and uses native-section cancellation fences; L264-305 `retireOnError` deliberately suppresses reusable task failure, drains resource closures, then executes `onRetire` and closes ports. Negative oracle: reply loss, late host response or ordinary success cannot serve as native-resource disposition; no successor may reuse an unconfirmed prior task.

**PAIR-R20B-02 — SQLite reader child close is distinct from delivered read.** `sqlite-readonly-worker-session.ts` L40-55 requires exact runtime generation, transport owner, cwd and complete environment for reuse; L127-144 waits broker cleanup on a child lacking confirmed exit; L198-218 resolves native `closed` on observed close event. L239-289 rejects malformed/stale sequence IDs and on some native result errors waits for native close instead of letting a snapshot directory disappear. L313-408 binds expectedIdentity and serialized read-only operation under size budget, AbortSignal and caller-owned deadline; L411-438 sends `close` and waits for `closed` with bounded termination escalation. Negative oracle: per-request result or AbortSignal alone cannot release a process that has not closed.

**PAIR-R20B-03 — bounded pool must hold quarantined slots.** `sqlite-readonly-worker-pool.ts` L38-77 sets 4 child slots and 60-second idle; failed close quarantines a slot while holding capacity. L83-159 binds pageCache.begin/step to a single read-only worker scope, forbids step without begin and requires identical launch identity, and rejects if all slots are quarantined. L208-298 serializes each slot via tail and closes child after failure or when runtime's native-close capability cannot guarantee release; preserves cleanup failure alongside read error. `sqlite-readonly-worker-context.ts` L41-65 closes scope by aborting and joining pending reads, child and retained worker lease. Negative oracle: scope A cannot recycle quarantined child to scope B nor let pageCache.step run with a new generation.

**PAIR-R20B-04 — staging token is an actual SQLite transaction fence, not a pathname-only marker.** `sqlite-staging-token.ts` L27-76 validates directory and token identities and pre-existing journal/sidecars; new create-only marker is written with `wx`; L91-149 begins IMMEDIATE for create, ordinary BEGIN for read, EXCLUSIVE for reclaim; destructive retirement commits `PRAGMA user_version=1` and retires the database admission. Negative oracle: replacement inode, active reader or current-layout unexpected child prevents destructive reclamation.

**PAIR-R20B-05 — cleanup budget and age are not authority to remove live data.** `sqlite-snapshot-staging.ts` L75-128 has 512 MiB reclamation per pass (first oversized candidate admitted to avoid starvation); current generation 15-minute minimum age, legacy 24-hour grace; per-directory token/ownership/cutoff must still succeed. L130-166 runs async reclaim under retained work and its own cancellation owner; L249-320 joins allocation, abort and cleanup errors and uses exclusive creation token. Negative oracle: age or cache size alone cannot delete live reader bytes; failed cleanup remains a reported failure, not successful disposal.

**PAIR-R20B-06 — native resource and host must acknowledge allocation before publication.** `sqlite-readonly-native-resource.ts` L39-127 requires host cleanup owner port; `ownerPort` loss leaves an explicit `SqliteSnapshotCleanupError`, and `allocated` must be acknowledged before returning path. Negative oracle: an unacknowledged directory may not publish and cannot be considered erased on worker exit or owner disconnect.

**PAIR-R20B-07 — broker close receipt is a separate authority.** `spawn-broker/resource-host.ts` L110-190 tracks owner message sequence and buffered bytes, and rejects resource release before `closed`; L208-280 makes `resource-closed` settle close while `resource-failed` explicitly does **not**. `spawn-broker/host.ts` L384-468 treats lost IPC after readiness as unknown command outcome and retains child/process-group cleanup. **PAIR-R20B-08 — updater generation deadline only bounds warnings.** `runtime-worker-generation.ts` L29-113 joins all registered owners, then native terminations, with 10,000 ms `raceWithTimeout` triggering a diagnostic; it still awaits actual termination. Settlement failures are aggregated, and `release()` only occurs when warranted.
