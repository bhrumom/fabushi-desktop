## R55-MAIN-POST-01 — Swallowed MessagePort failure can strand a request Promise

- source/electron-main/coordinator/coordinator-main-legs.ts blob 52a924ad99d57cca64fbd23856d5eccf8655f137 L5-L9: adoptPort wraps port.postMessage(frame) in try/catch. A thrown post error is only passed to optional reportFailure("leg-post",error); it is not thrown or used to settle the port/client. Separate revoke/replacement does dispose the client, but a post failure alone does not prove such disposal.
- source/electron-main/coordinator/coordinator-main-port-client.ts blob 80c74f9116b39b91b18cf6ca95f41ee88e7fed62 L5-L16: call creates session-local m-N request identity, inserts pending Promise **before** endpoint.post({kind:"request",requestId,method,args}) and returns the Promise. Since endpoint.post's error is swallowed, a thrown post can leave pending unresolved until another close/settlement occurs. settleReply matches only requestId; m-N is not durable mutation identity, source account epoch or settings revision.
- source/shared/rpc/coordinator-port.ts blob b79cce9ad413e5e0a775996f29ca7109a44ad208 L4-L12, L35-L59: request fields requestId/method/args and OK result status/value contain no mandatory account generation or Settings commit revision. Protocol version 1 is a lifecycle handshake version, not a write receipt.
- source/node-agent-coordinator/src/renderer_port_server.rs blob ede3e482d6d29847fb56ac1d0f2d77524331f55e L100-L110 enforces per-session requestId uniqueness and L129-L136 emits replies only for live pending requests: partial transport integrity, not durable or cross-account policy integrity.

**Independent oracle AR-MAIN-POSTFAIL-55 — NOT RUN:** Controlled MessagePort throws on the settings mutation post after normal hello without closing port. Require terminal caller error, pending cleanup, no claimed Host persistence or infinite resync hold. Independently release/recreate a healthy port and check no duplicate replay. Use explicit bounded watchdog; never equate a test timeout with a passing contract.

## R55-ORDER-02 — Serial Host arrivals do not serialize independently dispatched Coordinator HTTP issue order

- source/shared/rpc/coordinator-main.ts blob 9ee4b210ea92fbaeb4933b41ccb8e22ae5f3f4f3 L7-L8 lists getHostSettings and setHostSettings as object/no-arg methods, without an account slot in their typed descriptor.
- source/node-agent-coordinator/src/main.rs blob c822c07dff3027a22a658d1ece6aefe919691365 L2517-L2684: dispatch_to_host creates host_request_id as carrier name plus requestId, saves PendingHostRequest tagged with **Host process generation**, and spawns a **separate std::thread per incoming request**. Independent threads run dispatch_gateway_command, may arrive at Host HTTP/owner queue out of issue order, and resolve replies against the pending transport ID. execute_actions L2712-L2790 dispatches via this function. The generation fence is for Host lifetime; it is not an account policy revision.
- source/host/src/host_gateway_api.rs blob e93659285baf4903d3c97cf85629864341ad4126 L170-L171 assigns getHostSettings/setHostSettings to Settings. source/host/app/src/main.rs blob 8e19361b3b278d085927a84ea4c8ce8c3fe3de80 L10392-L10401 sends setHostSettings to call_host_lane, L4668-L4684 enqueues HostLaneRequest::Gateway on mpsc and awaits up to 120 seconds. L10745-L10785 dispatch_gateway_call routes through grok_gateway_call/Host JSON fallback.
- **Correct narrow positive:** All examined Host gateway requests entering the Host owner lane serialize by **lane arrival order**. This does not imply FIFO of MainData issue order: upstream Coordinator HTTP workers can reorder before the lane. A 120-second caller timeout also cannot prove any enqueued write was undone. Do not falsely allege Host lane itself executes gateway mutations concurrently.

**Independent oracle AR-COORD-FIFO-55 — NOT RUN:** Submit two MainData settings mutations with distinct requestIds. Hold the first Coordinator-to-Host dispatch before lane arrival, allow the second into Host, then release the first. Record issue ID, HTTP entry, lane entry, durable settings, Host readback and actual effective AutoReview gate. Require a defined account/epoch policy that rejects stale A or preserves the required order; mere matching reversed transport replies is insufficient.

## R55-LATE-CANCEL-03 — Reply mapping cancellation does not establish mutation rollback

The worker may still mutate Host; its result has no pending reply destination. Cancellation of the transport reply is not cancellation of the external side effect.
- source/electron-main/coordinator/coordinator-account-runtime.ts blob 03d048882d1c282213f01a2a05f3420872cad6fd L103-L119 serializes observed account changes with version checks. - source/host/src/extensions/settings/settings_service.rs blob f34a4d90ac1bf5a3b8208cc4d573ea97c9f8da72 L911-L1079: set_host_settings applies MCP account scope only if included in update L921-L938; it writes autoReviewInstructions at L995-L1005 without mandatory caller account epoch; persist L1050, reread projection L1078. apply_account_scope L1239-L1269 and clear_account_sensitive_settings L1271-L1284 clear prior account policy upon scope change. An *unscoped* old-account AutoReview mutation arriving after B scope change could add an A rule under B. This is a source-supported **possible schedule**, not a claimed observed incident.

**Independent oracle AR-LATE-HOST-WRITE-55 — NOT RUN:** Hold account A's accepted Host mutation after Coordinator worker dispatch; perform authoritative A→B transition and B settings persistence; revoke old port; then release old A request. Independently inspect B Host disk, next B effective policy and reply. A rule must never survive under B; return failure/unknown/reconcile as appropriate. Repeat with cancel, Host restart and stale success. Verify actual side effect rather than treating transport Cancel as reversal.
