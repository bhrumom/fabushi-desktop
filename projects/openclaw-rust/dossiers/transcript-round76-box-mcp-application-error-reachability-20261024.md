## R76-BOX-MCP-500-DISCONNECT-50 — deterministic Box protocol failure becomes gateway-unreachable

1. The bundled managed daemon `source/box-exec-daemon/src/server.rs` blob `a40dc3b5f78e414c3ac302137668f1d5be8dc73f` L1534-1620 emits a control `Throw` with error text `Unsupported ExecServerMessage case: unset` and structured code `BOX_EXEC_UNSUPPORTED` when its decoded Exec request has no recognized oneof; it then emits `close(id)`. Round75 already establishes why canonical MCP raw fields 11/36 decode into that unset case in this receiver.

2. The shipping Host decoder retains the daemon's structured control error initially. `source/host/src/box/generated_production.rs` blob `81f5a74dbf0ebc3700f177639bdd875f8c00eb56` L1330-1375 decodes control field 2 into `BoxRemoteExecControlMessage::Throw { id, error, stack_trace, error_code }`. `source/host/src/box/box_remote_accessor.rs` blob `fd74139f8e75e9635c85faf43de2637bbcbe4686` L270-350 makes `BoxRemoteExecManager::create_exec_instance` return `BoxRemoteExecError::RemoteThrow` with all three values when it sees that control message.

3. The structured Box code is then dropped at the Host application boundary. In `box_remote_accessor.rs`, `Display` for `BoxRemoteExecError::RemoteThrow` writes only the human `error` string; `ProductionBoxExecError::Display` in `generated_production.rs` delegates to that display. `source/host/src/extensions/mcp/production_box_state.rs` blob `ed10c6b76df61a0f3fdf5aa1f60844ace5f172b2` L149-163 maps `execute_raw_resource` failure with `error.to_string()`. Thus `BOX_EXEC_UNSUPPORTED` is no longer represented as a machine-readable code before the Host gateway response.

4. `source/host/app/src/main.rs` blob `8e19361b3b278d085927a84ea4c8ce8c3fe3de80` L9288-9308 maps that string to `GatewayCommandError::Internal`. `source/host/src/gateway_command_error.rs` blob `a7827b29c7f53899b1f34e7c989849816f4090fb` L17-35 maps every `Internal` to HTTP 500. `source/host/src/gateway_server.rs` blob `1ce506ae0bc75ee96418e55eb64a935dd7865ac0` L1220-1325 responds to command failures with JSON `{"error": error.to_string()}`; no Box error-code field is carried in this selected path.

5. Coordinator `source/node-agent-coordinator/src/gateway/gateway_request_dispatcher.rs` blob `38ca19db76493f9c2bca8862b484d61b7e74f47c` L13-35 defines the outward code `gateway-unreachable` for `GatewayDispatchError::Unreachable`. The HTTP dispatcher at L180-225 classifies **every Host HTTP status >=500** as `Unreachable { outcome: ReachabilityOutcome::Http(status), message }`, even though this particular 500 is a deterministic Box application/protocol response from a reachable Host. Therefore the MCP unsupported condition is transformed from Box application failure into Host gateway reachability failure.

6. The misclassification mutates Coordinator connection state. `source/node-agent-coordinator/src/main.rs` blob `c822c07dff3027a22a658d1ece6aefe919691365` L2630-2695 calls `gateway.transport_down(outcome)` for every `GatewayDispatchError::Unreachable` before replying. `source/node-agent-coordinator/src/gateway/gateway_client.rs` blob `67c666d4b3ec716aca60763bb53c594f066d0660` L130-190 and L335-385 implements `transport_down` via `GatewayClientState::disconnected`, which sets `connected=false`, `stream_live=false`, records the outcome and increments reconnect attempt for retryable outcomes. `source/node-agent-coordinator/src/gateway/gateway_reachability.rs` blob `faa3f917969a9d6b76c94597c5dce95aea1e4c2c` L1-35 explicitly marks `Http(500..=599)` retryable with transport kind `http_5xx`. The connection object is not erased and endpoint generation is not automatically advanced, but the live connection state is deterministically moved to disconnected/reconnect handling.

7. Electron ultimately receives a Coordinator failure rather than the original Box code. `source/electron-main/coordinator/coordinator-main-port-client.ts` blob `80c74f9116b39b91b18cf6ca95f41ee88e7fed62` L1-15 rejects a failed reply as `CoordinatorMainPortCallError(outcome.failure.code, outcome.failure.message)`. On the selected path that code is `gateway-unreachable`; the original `BOX_EXEC_UNSUPPORTED` code has already been discarded. `source/electron-main/adapters/mcp-oauth.ts` blob `ffbc225bfaaccbab7960ff8df31039553efdf1ec` L192-225 simply awaits that Coordinator call, so it does not restore Box-domain classification.
