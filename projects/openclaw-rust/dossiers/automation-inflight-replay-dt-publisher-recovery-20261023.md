## 2. OCRM-REC-AUTO-01: persistent run ID de-duplicates a record, not execution

**Exact producer/owner/caller proof:** `source/host/src/automations/automation_store.rs` blob `8ffd2175c7afb65611f65a1d56f3368b79881220`, L24-27 and L40-46:

1. `FileAutomationStore` owns per-automation `automation.json` and `runs.json`; `read_runs` returns an empty list after missing/unreadable/malformed JSON. `record_run` writes `last_run_at` in the config. `begin_run(id, ..., run_id)` reads existing runs; when the supplied run ID exists it **returns the pre-existing AutomationRun** with no new insert, regardless of `running` / terminal status. Otherwise it inserts a `running` record and truncates to `AUTOMATION_MAX_RUN_HISTORY`. `finish_run` sets `ok` or `error` on a matching ID, but does not represent an outcome-unknown lease/reconcile state.
2. The **actual caller**, `source/host/src/extensions/transcript/automation_run_path.rs` blob `7bedae399879f7269cfded2c5bf629ad9204a0b1`, L173-277, invokes `record_run`, `begin_run`, computes a wake prompt, and unconditionally invokes `execute(&prompt)` for the returned run (including a previously present ID). It then overwrites that run's terminal status. Therefore `begin_run` alone does **not** prevent duplicate side effects if an accepted run with a still-running local record is delivered again after process death / lost completion.
3. The **upstream admission guard must not be erased**: `source/host/src/extensions/automations/fire_delivery.rs` blob `04e3a192e7fa9b1d3bda7ea1757084153679bd79`, L40-159, looks for a run by exact or coalesced run UUID and replays **terminal** `ok/error` completion without dispatch. However `existing_run_completion` returns `None` when its stored status equals `running`, allowing that fire to enter the execution path again when other trigger/revision checks pass. `source/host/src/extensions/transcript/automation_run_path.rs` L138-170 also suppresses overlapping **non-Event** executions by an in-memory agent+automation key; that in-memory set cannot survive a process restart, and Event triggers do not use the same suppressor.
4. `source/host/src/extensions/transcript/automation_runtime.rs` blob `2a30406f2dd138a29a9bb90cf9f5324aa944e731`, L558-638 and L705-727, maps backend scheduled run UUID into `run_background_automation_with` and then the run path. The per-agent `with_agent_mutation_lock` at L899-921 protects initial store/config inspection and later diff processing, **not the entire execute interval**. `source/host/src/extensions/session/agent_session.rs` blob `4d2cde4d9e1feb56f61a0b38268bf112a14a30b9` L532-537 delegates store opening to the canonical ProductionSessionWorkers.
5. Test scope: `source/host/tests/automation_store_contract.rs` blob `7d9c8c752bf0389be19eba234e506cda113004a4` tests CRUD, one begin/finish, bounded history and definition projection; it does not establish replayed in-flight execution suppression. `source/host/tests/automations_fire_delivery_contract.rs` blob `2c15c263d9b9bbaa3005536d4a3b890a631dd1cd` has `existing_completed_run_is_not_executed_twice` (terminal replay), not an independent running-after-crash side-effect oracle. These are observations of examined test coverage, **not** a claim that no other test exists.

**Crash-durability nuance:** `source/host/src/watched_directory.rs` blob `eb7bb0106966e9a8b5adb7205667ff81678dce80` L154-178 writes `path.<pid>.tmp`, renames, and on an existing-target rename failure removes target before retrying rename.
