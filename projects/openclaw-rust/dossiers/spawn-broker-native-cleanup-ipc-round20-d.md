## 3. New falsifiable source contracts; NOT executed in Actions

**PAIR-R20D-01 (PID identity and group custody, cleanup.ts L9–137):** groupGone probes the **negative** process group; original leader identity records process start time and optionally native unreplaced-child exit ownership. Group signaling of a detached child rechecks identity before TERM or KILL; a replaced or uncertain live PID is not a safe signal target. \`terminateLostBrokerChild\` joins actual tree/descendant exit, not just TERM delivery, and rejects if closure is still unconfirmed after grace plus two seconds. Negative oracle: PID reused after delayed cleanup must never be signaled as old resource, and deadline cannot count as successful cleanup.

**PAIR-R20D-02 (private group census, cleanup.ts L140–256):** a broker re-reads member census and each member's start identity immediately before signaling. Missing original broker group, unknown live member identity, or unavailable census is explicit failure. TERM then KILL applies only to still-owned group; rechecking prevents late numeric PGID escalation after group disappearance. Source test \`cleanup-group.test.ts\` L20–85 specifies moved-group, unknown-birth, PID-reused and stale escalation counterexamples; Windows skip means Windows final evidence still separately required.

**PAIR-R20D-03 (bounded IPC and capacity, ipc.ts L7–100):** 1 MiB maximum per IPC frame; serialized pending payloads bounded to 256 MiB and 1,024 messages. Ordinary sender holds a FIFO promise to preserve frame order. Handle-bearing payloads above one frame reject. \`reserve\` admits a frame before fork, but a queued \`initiateSpawn\` is re-invoked at the **last** native send so revoked launch authority fails closed. Negative oracle: queued prepare grant revoked while a 2 MiB command waits must not initiate a native process. \`ipc.test.ts\` L5–48 specifies this counterexample, but no local or current-H Actions execution occurred.

**PAIR-R20D-04 (reader frame isolation, ipc.ts L103–159 and resource-socket.ts L8–128):** receiver validates safe integral id, bounds, offsets, frame order and strict contiguous chunks; starting a different serialized message abandons incomplete previous assembly. Resource socket adds a separate 4-byte bounded length envelope, rejects zero/oversized/truncated frames and only regards close as a **transport** event. Negative oracle: malformed or interrupted frame cannot become a successful command or typed close acknowledgment; disconnect doesn't establish native resource disposal.

**PAIR-R20D-05 (broker subprocess admission, worker.ts L34–185,241–430):** broker retains owned native child with announced/exited/resultSettled/openPipes and (when detached) captured process-group identity. It first reserves the outbound response capacity; \`prepare-spawn\` waits explicitly for launch grant; it emits \`owned\` PID before exposing a newly-started process to caller. Failed pre-admission can prove no process was started; later delivery failure cannot. \`forget\` waits for exit, result, pipe-drain and detached group disappearance. Negative oracle: proxy failure after launch/PID ownership must remain possibly side-effecting.

**PAIR-R20D-06 (broker disconnect and native close, worker.ts L106–185,386–515,546–685):** worker on parent disconnect seals new admission, rejects pending launch grants, retires children and then waits **all** pending launches, native resources, process group drain, output closure before disconnect. Child report failure cannot be silently converted to a successful stop. Signal handler does not preempt owner while parent IPC connected. Negative oracle: killed broker, lost parent, canceled execa or child close cannot automatically mean pairing transaction rolled back.

**PAIR-R20D-07 (resource server persistent custody, resource-server.ts L38–163,230–490):** resource server validates the captured private endpoint, 32-byte secret, **same generation**, ID and module URL before creating one resource owner. A resource import may be asynchronous; parent \`resource-seal\` removes late-attachment authority and releases waiters. Native-owner \`resource-failed\` is distinct from \`resource-closed\`; private Worker socket close seals the target port only, while the broker retains \`closeOwner\` responsibility, including retryable ordinary close errors and terminal drain. Negative oracle: transmitting Worker's socket disappears while native close is pending; broker close must still join the single original close. \`resource-server.test.ts\` L18–107 defines this counterexample as a source test only, no current execution receipt.

**PAIR-R20D-08 (resource owner message ordering, server.ts L164–229; client.ts L16–224):** server ensures owner messages are applied in sequence and bounded even if copied over two transports. It returns explicit owner-received or owner-rejected receipts; one failed owner callback is not an ACK. Client can retry initial socket connection until captured startup deadline, but a transport lost after attach cannot reconnect to acquire new authority. Client close may retry after a close-error *only if* the original broker/native cleanup remains addressable; dispose() of the socket alone does not release native custody. Negative oracle: delayed duplicate owner message, transport loss or close failure cannot emit false successful cleanup.

**PAIR-R20D-09 (transferred output and release, worker-sender.ts L12–93; worker.ts L452–486,603–655):** for native pipe handoff the original broker waits for both send callback and exact \`pipe-received\` ACK before admitting next handle. Worker tracks \`output-drained\`, suppresses stale unmatched ACK, and may keep child after result until true physical exit and pipe release. Negative oracle: resolved tool invocation result alone cannot prove stdout/stderr delivery, pipe closure or native worker lease release.

**PAIR-R20D-10 (independent authority surfaces):** private broker bootstrap secret authenticates only a same-host native resource control channel. This is neither an OpenClaw device pairing credential nor a grant/revoke/role/scope/rotation authority. Native cleanup and pairing mutation settlement must be modeled separately by a unique accepted Rust owner, not by transferring proxy lifecycle events into business permissions.
