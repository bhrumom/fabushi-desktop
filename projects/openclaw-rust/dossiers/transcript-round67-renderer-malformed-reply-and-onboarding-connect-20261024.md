## R67-RENDERER-MALFORMED-REPLY-31 — pending removed without promise settlement

- Exact Renderer production client: frontend/src/production/coordinator-client.ts blob f120b9f600861560409d9a9cac6487cb5ec79e63 L98–128. Its reply gate checks kind="reply", requestId as string and outcome as an object; it retrieves the waiting entry and **deletes it from pending before checking outcome.status**. It resolves only outcome.status="ok"; it rejects only status="failed" with outcome.failure object. A reply with the correct outstanding requestId and outcome {status:"unexpected"} or {status:"failed"} without a failure object passes that outer gate, deletes the pending entry, and triggers neither resolve nor reject.
- L67–75 and L80–95 reject/clear only entries that **remain in pending**. Thus subsequent ordinary close, port replacement or successful dispose cannot settle this removed promise. This is a distinct conditional liveness failure from Round 66's synchronous request-post exception (where the async caller itself rejects and an orphan map entry remains). The malformed reply must actually arrive; **no evidence** that shipping Coordinator sends one.
- Protocol contrast: source/shared/rpc/coordinator-port.ts blob b79cce9ad413e5e0a775996f29ca7109a44ad208, parseCoordinatorFrame's reply path rejects an invalid reply outcome. The separate frontend/src/recovered/runtime/coordinator-source.ts blob db7859728adba5129fab1d0572720390807dabad L397–400 invokes this parser and breaches an invalid frame, but **the inspected production createCoordinatorClient path does not call that parser**. Do not treat validation in the other implementation as protecting this caller.
- Oracle R67-REPLY-SETTLE-67A (NOT RUN): actual admitted Renderer production client + fake transferred port; first complete ready handshake, post a request and then inject matching malformed reply with invalid status/missing failure, followed by close, replace and dispose controls. Require exactly-once rejection or a positively validated protocol breach without losing pending ownership; compare valid ok, valid failed, unmatched requestId, and syntactically malformed frames. Record requestId, phase, pending count, promise settlement and port release separately.

- source/electron-main/prefs/host-settings-fields.ts blob 70b39227c0dbcd3af9a4dd0787667be3477a95e3 defines onTransportConnected to set live and start detached onboardingSeen.absorbFromBox(). Count **duplicate invocation as wired**, a **disk write only when successful relevant read and mismatch occur**, and a stale overwrite as **conditional/testable, not observed**.
