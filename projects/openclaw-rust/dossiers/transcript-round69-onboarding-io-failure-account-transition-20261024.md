## R69-ONBOARDING-CLEAR-THROW-36 — a synchronous mirror-clear error skips the account preparer's cleanup body

1. `source/electron-main/prefs/host-settings-fields.ts` blob `70b39227c0dbcd3af9a4dd0787667be3477a95e3` L3: `onAccountDeparted()` first calls `onboardingSeen.abandonInFlight()`, then immediately calls `options.store.clearHasSeenOnboarding()` **without a try/catch**. `source/shared/node/settings/sand-settings-store.ts` blob `52aeef0a22edeb64dab446a4aecf8c79590ee90f` L113–117 implements that clear with synchronous full-file load/modify/writeFileSync/renameSync; a persistence error can throw synchronously. `load()` swallowing malformed-input errors does not catch the final write failure. This is a different failure from the successful-clear timing previously audited.
2. **Actual shipping caller**: `source/electron-main/coordinator/production-provider.ts` blob `3b7591fbaf07cd7a5b13bfda27bca717c8603e01` L509–515 prepares A departure in this exact order: set `localHumanId=null`, `context.accountLifecycle.beginTransition()`, call `context.hostSettingsFields.onAccountDeparted()`, **then** `return ports.account.prepareAccountTransition(...)`. A thrown mirror-clear error prevents the last call; it is not inside the latter function's `finally`.
3. `source/electron-main/coordinator/production-root-provider.ts` blob `24e924f3d52d41a0900314aa7c21d98804a9dc19` L72–87 owns the **skipped** preparer: attempt `coordinatorResync.pushHostSettings` account/MCP clear, and in `finally` execute `settingsStore.clearAccountScope()`, `clearGatewayDescriptor()`, `requireMcp().resetMcpManager()`. 4. **Actual error consumer**: `source/electron-main/coordinator/coordinator-account-runtime.ts` blob `03d048882d1c282213f01a2a05f3420872cad6fd` L289–355 catches `prepareAccountTransition` rejection/throw, calls `onProblem("account transition preparation failed...")`, then continues `stop(detachActive(), ...)`, subsequent reset and the conditional next-account authorization/start path. This does **not** establish a completed B login, a retained B permission, or an unauthorized call: later `scopeToAccount`, descriptor authorization, process exit and further I/O can independently limit effects. `source/electron-main/account/account-authorization.ts` blob `5470896e1a623e69ec3b326cb08a5fb9865fb737` L10–18 still scopes a successfully authorized B and may itself fail if I/O remains broken.
