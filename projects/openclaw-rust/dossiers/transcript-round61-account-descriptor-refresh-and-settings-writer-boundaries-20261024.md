## R61-BROKER-REFRESH-SCOPE-12 — cache fence is not the caller-result fence

source/electron-main/adapters/coordinator-gateway.ts, blob f2d6f2577b1500958e98a939c8b65dbad2da09be L27-76, obtains the current authenticated-account backend token and an accountScope-dependent descriptor fast path. source/electron-main/box/gateway-descriptor-cache.ts, blob 5720b185a80b1313e6ab4a42646dfe435d7f8b6f L94-110, returns a persisted encrypted descriptor only for the exact requested accountScope and freshness. But at L165-184, resolveLive captures scopeAtDispatch, gates live-cache/write updates on scope equality, **then returns connection unconditionally at L177** even if that equality became false. New constrained source conclusion: scope rotation prevents storing the old completed refresh as the new scope's descriptor; it does **not** by itself ensure that a retiring caller never receives the old connection result. Coordinator disposal and account-specific connector instance ownership may make that old result unusable. No shipping consumer executing stale A credentials under B was established, so no cross-account privilege escalation claim. Test actual callback consumers, dispose order and transport-auth receipts rather than assuming either exploit or safety.
