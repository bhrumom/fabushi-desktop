## R58-PERM-SAME-REQUEST-01 — a losing concurrent resolution can mutate standing policy or insert an approval

New distinction from R57's already recorded independent HTTP writer: this is a **same requestId, different resolution** race, before the unique settlement operation.

1. 3. source/host/src/extensions/local_tool_permission/local_tool_permission_controller.rs blob 2e7722129582974b7cdbacc058fca3dae490ba2c L740–749 reads and clones the pending under state Mutex, then **releases it**. L784–805 inserts StoredApproval into approvals_by_id **before** L808–813 calls settle_pending. The actual unique remove is later at L1070–1088. L814–817 calls note_permission_changed even when settle_pending returned None. No intervening re-claim or requestId-owned persistence transaction is present in this inspected function.
4. Consequently, under two accepted concurrent HTTP decisions for the same still-pending ID, both may pass the early lookup. One can settle; the other can still persist Always/Never (changing global future policy), or insert a one-time StoredApproval before its own settle_pending returns None. This is a concrete source-permitted interleaving, **not proof of an observed incident**. For Deny versus AllowOnce, an AllowOnce loser can insert an approval after a successful Deny settlement without the standing-permission notification path. Authorization consumes approvals at controller L423–453 and L678–694, so the leftover state is security-relevant; effective exploitability requires a real subsequent authorized scope call, and must not be presumed.
5. SettingsService blob f34a4d90ac1bf5a3b8208cc4d573ea97c9f8da72 L198–235 and L250–273 performs unversioned whole-file load/replace; the operation isn't transactional with controller settlement. Serial repeat after settlement is **not** the same schedule. source/host/tests/local_tool_permission_resolution_contract.rs blob 8fef441625960984a2d876179ddbedc9974c7f3d L26–34 covers serial idempotence only. source/host/tests/local_tool_permission_controller_contract.rs blob b2dfc05f64f541dc18ed5016a0097370cf9f2ce0 L90–155 and L331–374 covers ordinary waiter/approval/events, not competing HTTP results.
