## Failure ordering and bounded cost

The receipt starts `failed-or-incomplete` (25–33). Archive creation is exclusive (`x:gz`), so an existing archive is not silently reused or overwritten. The context manager exits before the second inventory digest, archive hash, size and final `passed` assignment. Creation/write/compression/close failure, missing inventory, changed inventory digest, archive hashing failure or `stat` failure takes the enclosing exception path while `result` is still non-passing (287–307). A partial archive may be retained as diagnostic evidence but cannot establish a successful capture receipt. There is no optimistic archive-specific success followed by unchecked finalization.

The second inventory digest checks drift of the inventory file itself. The added code does not re-inventory every member during archival or independently validate the tar contents. That is consistent with capturing this closed fixture and the explicit future independent audit; it must not be described as an already executed archive-equivalence proof.

The performance increment is bounded to one existing consumer subtree containing two fixed fixture cases. It adds a streaming compression pass, an archive hash pass, another inventory hash and a file-size query, with one compressed file of additional disk use. It introduces no additional source build, subprocess, provider request, effect, product test or recursive walk of broad temporary roots. `file_digest` streams file bytes. `tarfile` keeps per-member metadata, so this review does not claim constant total memory. No measured timing/size/peak-memory result is available or implied, and no benchmark was run.
