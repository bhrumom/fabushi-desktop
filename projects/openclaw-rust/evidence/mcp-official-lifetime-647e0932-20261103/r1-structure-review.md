## Source conclusions

**Ownership and reuse.** `createMcpRuntime` retains one `current` attempt and its existing `isCurrent`/`requireCurrent` boundary (`mcp-runtime.ts:61–73`). `forwardAuthCompletion` checks that same identity before publishing and again after synchronous broadcast reentry (`:75–79`). The factory callback at `:114` supplies `[]`; the legacy observer at `:153–155` supplies `[completion]`. There is no new epoch, account key, callback registry, token cache, manager registry or permission predicate. The new callback remains a runtime factory option and is captured by the production join rather than becoming a separate desktop-manager policy surface.

**Credential contract.** The default official getter at `adapters/mcp-oauth.ts:250–257` now calls `options.getAccessToken({ backendUrl })`. That option retains its entry, post-auth-service and post-token checks (`mcp-runtime.ts:106–112`), with the supplied backend forwarded once. The existing OAuth adapter still fixes the broker origin and uses this getter for start, poll, acknowledge, cancel, refresh and revoke (`official-mcp-oauth.ts:23–30,58–77`). Disposal's best-effort cancellation therefore cannot acquire a replacement credential after reset has synchronously detached the attempt; rejection is consumed by the existing cleanup path. Nothing retains a token or redirects an old operation to B. An HTTP call after a token has already been returned is explicitly outside this getter fence, as MO-04 requires.

**Write admission and already-entered work.** `OfficialMcpService.scope()` now checks the same irreversible latch on both sides of its existing awaited scope lookup (`official-mcp-service.ts:32–40`). `mutate` retains its existing queue and state/revision contract, then rechecks activity immediately before `ports.write` with no intervening await (`:61–76`). The final check matters independently because the caller continuation after `await this.scope()` is another scheduling boundary. Once `ports.write` has been invoked, no new post-write check overwrites its outcome. The unchanged facade can subsequently refuse its `servers()` read after disposal (`desktop-mcp-manager.ts:211–215`), which matches the source contract and the admitted-write positive control. The service still owns existing official policy pending Rust migration; this patch does not expand that ownership.

**Completion compatibility.** The official payload remains `{ status: "changed", provider: "fabushi-official" }`; the runtime invokes its refresh port with zero arguments. The legacy completion remains the refresh argument. Both the root provider (`adapters/mcp-oauth.ts:159–165`) and fallback resolver (`:278–279`) fit the optional completion contract. The production Host port and desktop consumer already accept optional completion and convert absent/null completion to the existing empty refresh options (`main-production-services.ts:301–329,754–756`; `mcp-desktop.ts:8`). A synchronous broadcast reset allows the admitted broadcast and prevents its subsequent refresh without erasing B's attempt.

**Authored-control reachability and causality.** The fixture calls `createProductionMcpOAuthPorts()` and `createProductionMcpOAuthAdapter(ports).create(context)` directly (`mcp-runtime.contract.test.ts:1915–1919`); it does not replace `createManager` or the runtime/facade/service. Prototype controls intercept only native-store `reveal`/`upsert`, while the real vault selects and constructs the scope-specific store; its destination is asserted (`:1818–1842`). The legacy discovery warm path is refused at credential I/O before its Connect transport can use a socket. The service-await control arms from the real snapshot vault read; the final-scope control similarly arms the subsequent real scope peek. These gates decide ordering rather than guessed microtask counts.

The parameterized additions account for 14 cases: two credential-await boundaries; reset/dispose cancellation; current credential error/null behavior; poll failure/ready; entered acknowledgment; disconnect revoke success/failure; synchronous broadcast reset/current replacement; final-scope write refusal with exact B bytes; and entered write success/failure. The acknowledgment and write controls distinguish admitted outcomes from fresh admission. The disconnect test observes local removal before remote revoke, then checks old completion suppression. Existing MC observer controls still pin legacy completion forwarding and reentrant reset (`:515–550`).

**Cleanup and selection.** The fixture owns its explicit 2-second poll handles, forwards unrelated timeout durations and clears only handles from its own weak set (`:1873–1888`). Tests release held gates in `finally`; operations with returned promises are settled before fixture teardown. The idempotent disposer tears down the actual adapter, checks no owned poll remains, restores all test mocks and both environment variables in `finally`, then removes only its own temporary root (`:1755–1783`). `setImmediate` drains the finite released continuation chain; elapsed poll delay does not establish the race. Top-level tests do not opt into concurrent execution; the existing Node command runs separate contract entries as test files.

The selected existing renderer lane is sufficient by source: `rust-desktop-runtime.yml:4761–4777` invokes `build:electron -- --plugin-skills-contracts` and the whole MCP runtime contract bundle without a name filter. `desktop/scripts/build-electron-runtime.mjs:19–36,89–110` builds that exact test entry with the shipping esbuild options and Node 24 target. The workflow binds the tested checkout to the event/optional expected SHA (`:4622–4650`), and its source/project path triggers include this scope. The general TypeScript/test lane also includes the target but is conditionally skipped for OCRM plugin scope; the active bundle lane is therefore the relevant selection. No new workflow is needed. This is reachability inspection, not a claim that compilation or execution passed.

**Performance.** Added production work is bounded synchronous identity/latch checking and a shared callback dispatch. It adds no network request, disk operation, timer, retry, scan, queue or retained collection. `scope()` performs the same number of account lookups, and official token acquisition reuses the existing runtime getter instead of making a second acquisition. No concrete performance regression follows from the changed source. No benchmark or measured latency claim is made.
