## Finding DTR-R2-STRUCT-01 — P2: quadratic deduplication runs before pairing admission

**Path/symbol/lines:** `source/host/src/device_pairing_owner.rs:132-145`, `canonical_scope_strings` and `normalized_scope_strings`; reached by `normalized_wire_scopes` at lines 154-164 and `WireRotationRequest::parse` at lines 184-190. `rotate_token_with_authority` parses the complete request at line 1406, before locking/beginning the transaction at lines 1409-1413 and before `admit_paired_operator` at lines 1414-1416.

Each new distinct scope scans every prior retained scope through `scopes.iter().any(...)` at line 136. For `n` distinct nonblank strings, this performs `n(n-1)/2` string equality checks before the later UTF-16 sort. R1's wire normalizer appended scopes and sorted/deduplicated them; R2 adds the quadratic pass to that public request path.

**Concrete triggering scenario:** a genuinely issued current `operator.read` credential sends `POST /api/device.token.rotate` with no `x-sand-scope` header and a valid closed object whose `scopes` contains 100,000 distinct short strings such as `operator.x000000` through `operator.x099999`. The body is approximately 2 MB, far below the existing Gateway body limit (`gateway_server.rs:55-56`, enforced at lines 904-924). The DTR method deliberately bypasses the generic literal-write prefilter (`gateway_server.rs:1901-1915`), a read bearer is not a node, and the actual App's ordinary operator request authorization returns `Ok(())` (`app/src/main.rs:13338-13345`). The request therefore reaches the bound hook at `gateway_server.rs:2009-2015` and the real owner. Before the expected pairing-policy 403, the new helper performs 4,999,950,000 prior-string comparisons. The authored read-grant HTTP refusal control at `device_token_rotation_wire_gateway_contract.rs:871-881` also explicitly expects one bound dispatch in this case.

This is a concrete resource amplification regression: low-privilege authenticated requests can consume sustained Host CPU before the decisive permission refusal, and concurrent connections each have a thread (`gateway_server.rs:821-837`). The same canonicalizer also runs for stored/live/approved reads under the pairing mutex, so large persisted grants can make ordinary credential admission more expensive. The operation-count claim follows directly from the loop; elapsed time, an executed exploit and a benchmark result are **not** claimed.

**Specific fix:** retain one private canonicalizer, but track seen trimmed strings in an existing standard-library set while appending only first occurrences to the output vector. An order-preserving vector plus `BTreeSet` membership is sufficient and needs no dependency; a suitable `HashSet` also works. Preserve ECMAScript trimming, exact grant comparison, first-seen order for native producers/authentication, no implied permissions at the canonicalization layer, and the separate final UTF-16 sort/implication expansion in `normalized_wire_scopes`. Preserve the explicit DPA Rust-trim request adapter. Moving admission earlier alone would leave the valid pairing-caller cost problem and would alter request/error ordering; removing the quadratic membership scan addresses the actual defect.

**Focused verification after a fix:** keep all existing Unicode, producer, omitted/explicit DPA and result-order controls. Add an appropriate large-distinct-input/duplicate/refusal control to the existing owner/HTTP contract targets in Actions, with a normal positive control and unchanged-state assertion. Avoid a machine-sensitive tight timing threshold as the sole oracle. Source review should confirm bounded set lookup replaces the nested vector scan. Do not run a local benchmark or create a second harness.

## Existing-owner and R2 contract assessment

**One production authority remains.** `host_gateway_api.rs` registers the exact wire method under `HostGatewayOwner::DevicePairing`; Gateway classifies it as mutating/operator-only and routes every native or paired HTTP request through the new optional-proof hook. The default hook is a fixed 403. The actual `UnifiedGatewayApi::rotate_device_token` records one desktop contact and delegates to its existing `self.device_pairing`; generic trusted-native dispatch reaches the same owner through `handle_pairing_command`. No alternative policy store, token registry, schema, runtime, scheduler or cancellation owner is introduced. No new dependency/build reach appears in this 16-path publication.

**Scope policy reuse is materially improved.** `role_scope_allows` now compares canonical grants exactly. The shared canonicalizer is used by native stored-scope production, fresh authentication's public/sealed snapshots, live/approved reads, DRT's selected operator grant and pending scope-set comparison. Role/identity normalization remains separate. `rotate_token` still uses `normalized_authority_strings` only for the explicit legacy DPA request adapter and its role handling; omitted stored grants use credential canonicalization. The authored R2 controls exercise an actual issued NEL literal against DPA/DRT/DVR/DTR, distinguish NEL from BOM, preserve an ordinary usable literal-bearing credential, and retain genuine admin/pairing positives. I found no second interpretation path in the inspected pairing-management consumer call graph. The performance defect above is in the implementation of this otherwise appropriate shared seam.

**Selected-primary repair is at the correct atomic boundary.** `rotate_token_with_authority` validates the original `roles_json` strings, retains the original parsed array, and appends only the normalized selected primary role when normalized membership is absent (`device_pairing_owner.rs:1443-1458`). If membership already exists, `materialized_roles` is `None`; `COALESCE(?4, roles_json)` preserves the original column bytes. The token, selected role array, node-only retained/pending surfaces and checked revision participate in one IMMEDIATE transaction and one commit (`1519-1536`). Other primary roles are not materialized. Shared caller currentness still requires role-array membership (`1602-1604`), so a later withdrawal cannot use the primary label to revive a credential. Replacing the selected token also prevents an old selected proof from becoming current merely because array membership was restored.

**Decisive approval selection fixes the actual consumer seam.** `current_pairing_record` selects `COALESCE(approved_scopes_json, scopes_json)` in SQL before decoding (`1594-1601`). An unused malformed legacy fallback no longer invalidates a successor issued against valid approval. A malformed decisive approval, or malformed fallback when approval is SQL NULL, still fails closed. The legacy DPA target read remains `rotation_record`, which deliberately reads raw device scopes for its separate defaulting contract. No column is repaired, discarded or silently rewritten by currentness.

**Mutation/network lifetime remains separated.** Decisive caller and target reads happen after the IMMEDIATE transaction begins. Pairing policy and target nondisclosure precede target lookup. RNG generation follows admission/validation; the selected metadata object is preserved except for specified generation fields. One checked target update and one existing checked revision increment precede commit. Delivery uses the sealed paired identity after commit and does not perform a stale postmutation check that would suppress a successful self response. Native/cross-device responses omit the bearer. No network write, retained wait or callback is performed while the mutation transaction is open.

**Retained and node consumers continue to reuse their established owners.** The event and LocalExec/WebAuthn loops still use `validate_paired_device_authorization` at existing admission/wake/effect boundaries; there is no added polling or registration registry. The R2 primary-only test reconnects through the real retained entry, acknowledges teardown before reopening, and proves later role-array withdrawal closes only the selected credential. EOF requires a successful bounded read to actual EOF; a timeout is a failure. The App tests reuse `NodeProjectionFixture` and actual `project_openclaw_node_list/status` helpers. The stored remote pairing remains a disconnected projection, disconnected runtime history is not promoted to a live connection, and `sand-local-node` remains governed by the existing node runtime. Physical remote teardown, worker/APNs/cache behavior is correctly left unaccepted.
